# Worker contracts

Sol inspects enough current evidence to issue a competent assignment. Do not replace missing understanding with a large copy of conversation history.

Every assignment contains sender/reply path; exact question and result; relevant inputs and source references; exclusive writable files; preserved behavior and constraints; required methods; executed acceptance checks; output format; budget and retry boundary; exact model/effort; and stopping or escalation condition. State whether it is read-only or has a bounded write path.

For development, require the smallest sufficient change, existing components where appropriate, no speculative abstractions or unrelated refactoring, and no dependencies without required authority. Return changed files, exact checks and failures. Hashes establish identity, not quality.

Sol confirms active write scopes do not overlap. Count requested, queued, running and completed workers separately. Workers return outcomes to Sol; Astra receives decisions, contradictions and integrated evidence. Use independent review where it resolves material uncertainty. Multiple model opinions cannot establish unsupported facts.

The required review order is Luna → Sol → Astra, reversing task delegation. A worker returns its artifact plus executed checks. Sol reviews that evidence before integration, and Astra reviews the integrated result. Send a rejected result back with the exact failure, owned correction scope and relevant acceptance check. Only affected review/checks repeat after correction; a copied PASS or unchanged agent agreement is insufficient.
